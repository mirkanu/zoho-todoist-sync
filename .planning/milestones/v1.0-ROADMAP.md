## Key Accomplishments

1. **Loop-safe canonical hash** — SHA-256 over `{title, due_date, priority, is_completed}`; zero infinite loops observed in production
2. **Zoho OAuth + field resolution** — Proactive token refresh at 50min; `Todoist Task ID` api_name resolved at startup via field_label match
3. **Full read/write CRUD** — Create, update, complete, delete in both directions with correct priority mapping (Highest→4, not inverted)
4. **arq worker** — Per-task Redis SETNX lock, `_job_id` dedup, 3-retry backoff (5s/15s/60s), 2s Zoho defer
5. **HMAC-verified webhooks** — Both Zoho and Todoist handlers; enqueue within 200ms; fast-return before any DB I/O
6. **Reconciliation + orphan detection** — 15-min sweep catches missed webhooks; hourly orphan sweep with 2-cycle confirmation
7. **Observability** — `/health` endpoint, daily summary cron at midnight UTC, 90-day audit log cleanup
8. **Migration** — 42 existing Make.com pairs linked into sync_state; no duplicate tasks created; Make.com replaced

## Architecture Decision Log

| Decision | Outcome |
|----------|---------|
| Canonical hash loop prevention | SHA-256 over JSON(sort_keys=True). Stable across TZ/Unicode/CRLF. |
| Footer `[zoho:ID]` in Todoist description → **removed post-v1** | Quick task 260501-m0t removed footer scheme; sync_state DB column is now the sole ID linkage. Simpler, no fragility from user edits. |
| Zoho custom field `Todoist_Task_ID` | Resolved at startup via field_label match. Cached in `zoho_field_cache`. |
| Due date always date-only | `normalise_due_date` uses `fromisoformat().date()`. Fixes Make.com time-chip regression. |
| Todoist delete → Zoho delete | Treat as intent signal. Fire-and-forget Resend email. 404 is idempotent. |
| per-call httpx.AsyncClient | ZohoClient holds mutable access_token; shared client would cache stale token after refresh. |
